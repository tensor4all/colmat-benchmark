# Status of the published datasets

Written by hand. `INDEX.md` and `HISTORY.md` are generated by `scripts/gen_index.py` and CI compares
them byte for byte, so a status line cannot live there; this file is the place the index's readers are
sent to ([README.md](../README.md), [docs/results.md](../docs/results.md), [result/README.md](README.md)).
No result page is edited: the numbers stay in the repository as history; this file states their status.

Terms are the ones of [docs/provisional-and-clean-datasets.md](../docs/provisional-and-clean-datasets.md)
(**provisional**, **superseded**) and of the index (`partial`, `stale`). One term is added for cells:
**withdrawn pending re-measurement** - the cell stays published, and must not be quoted until a page
recorded by a harness at or after `7bb8105` (#49) replaces it.

## 2026-11-06: pages recorded before #49

Every page below `result/` was recorded before [#49](https://github.com/tensor4all/faer-benchmark/pull/49)
(`7bb8105`, 2026-11-06): the newest harness commit among them is `eeeaa363` (page `71b25ffb`, recorded
2026-10-31/11-01). Their `lu`, `solve`, `full_piv_lu`, `cholesky` and vendor-arm cells were produced by a
harness whose timed region included work the other row did not pay for. The cells are traced, call by
call, in [docs/measurement-audit-2026-11-06.md](../docs/measurement-audit-2026-11-06.md) (sections 2 and
6); what #49 changed is in its commit message and in `docs/reliable-measurement.md`, "Allocation and the
clock".

The status applies to every shape, memory order (c and f), dtype (`f64`, `c64`) and thread count in those
pages, because the harness path is the same for all of them; the audit read the 1T, c-order,
`linalg-small` values of pages `71b25ffb` and `2240b076` number by number and traced the rest.

### Withdrawn pending re-measurement

| family | which ratios | why (audit) |
|---|---|---|
| `lu`, `solve`, `cholesky` | fork vs upstream, fork vs MKL, fork vs OpenBLAS; all shapes | faer rows timed through owning routes (allocation, layout copy, L/U split or upper-zero loop); the fork row additionally ran a hand-written mirror of the library composite; the vendor row timed a copy, `ipiv` and LAPACKE internals. Audit section 6 |
| `full_piv_lu` | fork vs upstream, all shapes (no vendor route) | same mirror-versus-library difference. Audit section 6 |
| `qr_factor/n64` | fork vs MKL | the MKL cell is non-monotone (`n64` slower than `n96`) and cannot be explained from source. Audit section 6 |

Examples already visible in the pages: `solve/n256` 1.12x, `solve/n512` 2.33x, `qr_factor/n64` 1.37x.
Do not treat the examples as the list; the table is.

### What a reader may still use

| cells | use |
|---|---|
| `gemm`, `triangular_solve`, `householder_apply` (all arms, all shapes) | **usable**. Both faer rows and the vendor make the same kind of call (audit section 2); the `triangular_solve` 1.06-1.07x difference at n = 64/96 is not a harness difference the audit can see |
| `qr_factor`, other than `n64`: fork vs upstream | **usable**. Both faer rows run the same in-place body |
| `qr_factor` (other than `n64`), `qr`, `svd_values`, `svd_thin`, `eigh`: fork vs vendor | **one-sided**. The vendor row paid for a copy, workspace allocations and, for c order, transposes that the faer row did not, so "the fork is slower than MKL/OpenBLAS" stands as a lower bound on the gap, and "the fork is faster" is overstated. Quote only the first reading |
| `qr`, `svd_values`, `svd_thin`, `eigh`: fork vs upstream | **usable with the audit's caveat**: the fork row is a hand-written mirror of the library route (audit section 2); the audit rates the effect low for these families but did not withdraw them |

Nothing is withdrawn that the audit did not trace to a call; nothing the audit traced as unfair is left
usable.

## Closing an entry

Re-measure with a harness at or after `7bb8105` on the machine that recorded the dataset, publish
through the usual recorder, and edit this file to say which pages replaced which. The old pages are not
deleted.
